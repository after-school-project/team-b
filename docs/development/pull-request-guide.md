# After School Project PR作成ガイド

## 1. このガイドの目的

変更の目的、内容、確認結果、影響範囲を整理し、レビューする人が変更を理解できるプルリクエスト（PR）を作成するためのガイドです。

開発の進め方、コミット、レビュー・マージの共通ルールは[開発・コントリビューションガイド](../../CONTRIBUTING.md)を参照してください。

## 2. PRタイトルの付け方

GitHubのタイトル欄には、次の形式で記載します。

```text
type: #Issue番号 変更内容
```

例：

- `feat: #12 ログイン画面を実装`
- `fix: #15 ログインエラーを修正`
- `docs: #18 API設計書を更新`

`type`は[コミットメッセージの種類](../../CONTRIBUTING.md#commit-messages)と同じ分類（`feat`、`fix`、`docs`、`refactor`、`test`、`chore`）を使用します。各コミットではIssue番号は任意ですが、PRタイトルには関連Issueの番号を記載します。

## 3. PR本文の書き方

PR作成時には[PRテンプレート](../../.github/pull_request_template.md)が本文へ自動表示されます。説明コメントを参考に内容を記入します。自動表示されない場合は、テンプレートの内容をコピーして使用できます。

| 項目 | 記載する内容 |
|---|---|
| 概要 | 変更の目的や解決する課題 |
| 変更内容 | 実際に変更した内容の箇条書き |
| 動作確認・確認結果 | 実際に行った操作・テストと結果、該当しない項目や未実施項目の理由 |
| 影響範囲 | 影響する領域。「その他」を選んだ場合は具体的な内容 |
| レビュー時に確認してほしい点 | 特に確認してほしい部分。なければ「なし」 |
| PR作成前チェックリスト | タイトル、関連Issue、差分、機密情報、必要な確認の実施状況 |

確認項目は、実際に確認できたものにチェックを入れます。ドキュメント変更の場合は、記載内容やリンクの確認結果を記載します。該当しない項目や未実施の項目は、確認結果に理由を記載します。

Issueには着手時点で合意する受入条件と確認方法、PRには実際の確認結果を記載します。受入条件の番号（`AC-01`など）に対応させると、レビュー時に確認しやすくなります。

例：

```markdown
### 確認結果

- AC-01：有効なテストアカウントでログインし、ホーム画面へ移動できることを確認した。
- AC-02：誤ったパスワードでエラーが表示され、保護された画面を利用できないことを確認した。
- AC-03：停止中のテストアカウントではログインできないことを確認した。
```

## 4. GitHub右側の設定

担当者やラベルなどは本文に名前を書くだけで済ませず、GitHub右側の各項目で設定します。

| 項目 | 設定内容 |
|---|---|
| **Reviewers** | [共通ルール](../../CONTRIBUTING.md#review-and-merge)に従って設定します。 |
| **Assignees** | 原則としてPR作成者本人を指定します。 |
| **Labels** | 変更内容に合わせて設定します。 |
| **Projects** | チームのGitHub Projectを設定します。 |
| **Milestone** | 使用する場合のみ、対象Sprintを設定します。 |
| **Development** | 関連Issueを紐づけます。 |

## 5. レビュー・マージ

承認人数、指摘事項の修正、チェックの通過、`main`への取り込みは、[レビュー・マージの共通ルール](../../CONTRIBUTING.md#review-and-merge)に従います。
