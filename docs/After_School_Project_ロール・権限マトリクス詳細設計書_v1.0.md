## 1. 認可の基本設計

### 1.1 ロール構造

| **区分**         | **ロール／状態** | **認可上の意味**                                                           |
|------------------|------------------|----------------------------------------------------------------------------|
| **基本所属**     | 在校生           | 通常のコミュニティ機能、イベント申請。お知らせ投稿不可。                   |
| **基本所属**     | 卒業生           | お知らせ・イベント申請を含む通常機能。                                     |
| **基本所属**     | 学校職員         | お知らせ・イベント即時公開。                                               |
| **在校生の状態** | 卒業予定者       | 基本ロールは在校生。本人希望で卒業生検索に掲載可。                         |
| **追加管理権限** | 学校管理者       | 学校専用の登録審査・本人確認・監査・管理操作。卒業生との兼任は想定外。     |
| **追加管理権限** | アプリ管理者     | 一般的な承認・通報対応・ユーザー管理。基本所属の投稿制限は自動解除しない。 |

### 1.2 制限優先型の最終判定（CONS-05）

| **判定順** | **チェック内容**                                                         | **失敗時**     |
|------------|--------------------------------------------------------------------------|----------------|
| **1**      | ログイン／メール確認／学校の初回承認。未承認者は申請状況のみ。           | 対象操作を拒否 |
| **2**      | アカウント状態：停止中はすべてのコミュニティ・管理機能拒否。             | 対象操作を拒否 |
| **3**      | プロフィール状態：非表示中の投稿・編集制限、アプリ管理者の管理機能停止。 | 該当操作を拒否 |
| **4**      | 基本所属と追加管理権限：操作の必要なロールを持つか。                     | 対象操作を拒否 |
| **5**      | 操作対象との関係・区分：本人／他人、学校公式／一般、管理者本人の案件等。 | 対象操作を拒否 |
| **6**      | 申請・公開・削除・開催などの対象状態、期間、自己審査禁止・閲覧例外。     | 対象操作を拒否 |

原則：明示的に許可されたすべての条件が真の場合のみ許可。管理者権限で先行する拒否条件を上書きしない。コンテンツ強制非表示・復元に限る自己操作の既定例外（NO/EV）は、自己承認禁止の例外にはならない。

### 1.3 権限のライフサイクル

| **場面**                     | **確定仕様**                                                             | **参照**    |
|------------------------------|--------------------------------------------------------------------------|-------------|
| **最初の学校管理者**         | 学校指定の担当者をシステム管理担当者が初期作成、本人が初回認証情報設定。 | AUTH-18     |
| **学校職員アカウント**       | 学校管理者が個別作成、本人が初回認証情報設定。                           | AUTH-03     |
| **アプリ管理者任命**         | 学校管理者が承認済み利用者に付与・解除、操作履歴記録。                   | AUTH-04     |
| **アプリ管理者権限解除**     | ログイン維持・基本所属維持。管理APIは解除確定から即時拒否。              | AUTH-19     |
| **卒業区分変更／誤変更修正** | 学校管理者のみ。既存のアカウントと履歴は維持。                           | AUTH-11／24 |
| **学校管理者停止**           | 学校管理者のアプリ内停止・解除機能はMVP対象外。                          | AUTH-06-2   |

### 4.1 引継ぎと一時未割当

| **契機**                                 | **対象**                                 | **確定した動作**                              |
|------------------------------------------|------------------------------------------|-----------------------------------------------|
| **アプリ管理者プロフィール非表示**       | その管理者が担当する未対応／対応中の案件 | 学校管理者専用の引継ぎ待ちへ自動移行          |

| **qa.moderate / restore**              | 投稿者がアプリ管理者なら学校管理者のみ                           | 非表示・復元ログ／適用通知                     |
| **notice.approve / reject**            | 両管理者、アプリ管理者は自己申請不可                             | 旧公開版維持・審査結果履歴                     |
| **notice.hide / restore**              | 学校公式なら学校管理者のみ、卒業生分は両管理者（自己可）         | 理由任意・監査必須・通知なし                   |
| **event.approve / reject**             | 両管理者、アプリ管理者の自己申請不可、過去開始日なら保留         | 開催日条件・承認履歴                           |
| **event.hide / restore**               | 学校職員分は学校管理者のみ、在校生／卒業生分は両管理者（自己可） | 理由任意・監査必須・通知なし                   |
| **report.assign / reassign**           | 通常案件は両管理者、引継ぎ待ち／専用案件は学校管理者のみ         | 担当者変更ログ                                 |
| **report.evidence.read**               | 学校管理者のみ（削除済みコンテンツ）                             | アクセス制限・監査要件は後続詳細化             |
| **audit.read**                         | 学校管理者のみ                                                   | 操作ログは追加のみ、管理画面から更新／削除不可 |

### 6.2 技術に依存しない実装条件

- サーバー側の認可を唯一の決定源とする。画面非表示だけでアクセスを保護しない。

- ロール・アカウント停止・プロフィール非表示の最新状態を毎回参照し、権限解除直後のアクセスを拒否する。

- 本人所有チェックはクライアントが送ったactor_idを信用せず、認証済み主体とDB上の所有者を比較する。

- お知らせ／イベント審査は競合更新・二重承認を防ぎ、申請状態の条件付き更新を行う。

- 公開状態と開催／審査状態は独立して管理し、強制非表示解除が自動的に承認や開催中止解除をしない。

- 削除済みコンテンツの本文閲覧権限と保存された証拠閲覧権限を別々に制限する。

- 操作ログはアプリ管理者に開示しない。追記と期限による削除は信頼済みサーバー処理に限定する。

- 採用技術・テーブル・RLS式・関数・監査トリガーの構成はDB設計時に確定する。
