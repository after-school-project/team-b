# After School Project UIデザインガイド

バージョン：0.1  
作成日：2026-11-14  
対象：After School Project PoC

## 1. この文書の目的

さいたまIT・WEB専門学校のロゴカラーを基調に、在校生・卒業生・学校職員が使うアプリの見た目と操作感を統一する。

本書は、配色、文字、余白、レイアウト、共通部品、状態表示の実装基準を定める。

機能、画面遷移、認可、データの状態は既存設計書に従う。本書で機能や権限を追加しない。

参照資料：

- [PoC画面一覧設計書](./After_School_Project_PoC_画面一覧設計書_v0.2.md)
- [PoC画面遷移・状態遷移設計書](./After_School_Project_PoC_画面遷移・状態遷移設計書_v0.1.md)
- [PoC共通認可条件表](./After_School_Project_PoC_共通認可条件表_v0.1.md)
- [PoC API設計書](./After_School_Project_PoC_API設計書_v0.1.md)

## 2. デザイン方針

**落ち着いたネイビーを土台に、ブルーで交流の入口を示し、オレンジを小さなアクセントとして使う。**

学校のサービスとしての信頼感と、質問や交流を始めやすい親しみやすさを両立する。

- 本文を読みやすくし、投稿内容と次の操作を見つけやすくする。
- 白を中心とした画面に、ロゴ由来の色を要所で使う。
- 一般画面と管理画面で、色・部品・操作の基本ルールを共有する。
- 状態や重要度は、色と日本語ラベルを組み合わせて伝える。
- 装飾より、内容、権限、公開状態の理解を優先する。

ロゴの四角形を参考に、カードや区切りを整然と配置する。ひし形やオレンジの装飾を各所に繰り返すことは避ける。

## 3. カラーパレット

### 3.1 ブランドカラー

添付ロゴ画像から取得した参考値。正式なブランドカラーの指定値がある場合は、そちらを優先する。

| 名前 | HEX | 主な用途 |
|---|---|---|
| ブランドネイビー | `#1C2A54` | 見出し、主要ボタン、ブランド表示 |
| ブランドブルー | `#3297CA` | 選択箇所の補助線、アイコン、装飾 |
| ブランドライトブルー | `#7CBED3` | 補助装飾、ネイビー文字を載せる背景 |
| ブランドオレンジ | `#E89112` | 小さな強調、注目箇所のアクセント |

ブランドカラーは、すべてを同じ面積で使用しない。背景は白・淡いグレーを中心にし、ネイビーを画面の骨格として使う。

オレンジは削除や停止などの危険操作には使用しない。

### 3.2 UI用カラー

ブランドカラーに加え、読みやすさと操作の識別に必要な色を定義する。

| トークン | 値 | 用途 |
|---|---|---|
| `--color-bg` | `#F5F8FC` | ページ背景 |
| `--color-surface` | `#FFFFFF` | カード、フォーム、ダイアログ |
| `--color-surface-subtle` | `#EEF5FA` | 補助領域、ホバー背景 |
| `--color-text` | `#1F2937` | 本文 |
| `--color-text-muted` | `#526175` | 補足文、日時 |
| `--color-heading` | `#1C2A54` | 見出し |
| `--color-border` | `#D8E2EC` | カードや領域の区切り |
| `--color-control-border` | `#718096` | 入力欄、未選択のチェックボックス |
| `--color-primary` | `#1C2A54` | 主要ボタン |
| `--color-primary-hover` | `#152041` | 主要ボタンのホバー |
| `--color-on-primary` | `#FFFFFF` | 主要ボタンの文字 |
| `--color-link` | `#176B91` | 本文リンク、文字による操作 |
| `--color-focus` | `#176B91` | キーボードフォーカス |

薄い区切り線は装飾用途に使う。操作部品の識別に必要な境界には、濃い色の `--color-control-border` を使う。

### 3.3 状態カラー

以下はUIの意味を伝えるための補助色とする。

| 状態 | 文字・アイコン | 背景 |
|---|---|---|
| 案内・情報 | `#176B91` | `#EAF5FB` |
| 成功・承認 | `#166534` | `#ECFDF3` |
| 注意・承認待ち | `#92400E` | `#FFF7E6` |
| エラー・危険操作 | `#B42318` | `#FEF3F2` |
| 終了・取り下げなど | `#526175` | `#EEF2F6` |

「承認待ち」「承認済み」「却下」「中止」などのラベルを必ず併記する。色だけで状態を判別させない。

未読・既読は、背景色だけでなく、未読ラベルや文字の太さでも区別する。

### 3.4 文字と背景の組み合わせ

ロゴの明るい色は、そのまま白文字のボタンに使用しない。

| 組み合わせ | コントラスト比の概算 | 用途 |
|---|---:|---|
| 白文字／ネイビー | 13.92:1 | 主要ボタン |
| 白文字／UI用リンクブルー | 5.92:1 | 必要に応じた強調部品 |
| ネイビー文字／オレンジ | 5.63:1 | 注目ラベル |
| ネイビー文字／ライトブルー | 6.74:1 | 補助ラベル |
| 白文字／ブランドブルー | 3.27:1 | 通常サイズの文字には使用しない |
| 白文字／オレンジ | 2.47:1 | 文字用途では使用しない |

ブランドブルーは、白背景上の小さな文字や、選択状態を伝える唯一の手掛かりにも使用しない。

## 4. テーマとロゴ

### 4.1 テーマ

PoCではライトテーマを基準とする。

OSの設定だけで自動的にダークテーマへ切り替えない。ダークテーマは、配色と全状態を別途確認してから追加する。

現在の `globals.css` にある自動ダーク切り替えは、実装時に本方針へ合わせる。

### 4.2 ロゴ

- 正式なロゴ素材を使用し、縦横比を維持する。
- ロゴの色変更、変形、切り抜き、影の追加を行わない。
- 白背景を基本とし、周囲に十分な余白を確保する。
- ロゴ画像をCSSや文字で再現しない。
- 小さな表示では文字が読めるか確認する。
- シンボル単体の使用は、正式な素材・使用条件を確認してから行う。

ログイン画面では学校ロゴとアプリ名を明示する。ログイン後はコンパクトなブランド領域とし、本文の表示領域を確保する。

## 5. 文字

基本フォント：

```css
font-family:
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Yu Gothic",
  Meiryo,
  sans-serif;
```

| 用途 | サイズ | 太さ | 行高 |
|---|---:|---:|---:|
| ページタイトル | 28〜32px | 700 | 1.4 |
| セクション見出し | 20〜24px | 700 | 1.5 |
| カード見出し | 18px | 600 | 1.5 |
| 本文・入力欄 | 16px | 400 | 1.7 |
| ラベル・補足 | 14px | 400〜600 | 1.6 |
| 短いバッジ | 12px | 600 | 1.5 |

- モバイルのページタイトルは24pxを基本とする。
- 重要な説明やエラーメッセージを小さな文字にしない。
- 長い日本語本文は左揃えにする。
- 本文中のリンクには下線を付ける。
- 長いURLや英数字が画面幅からはみ出さないようにする。

## 6. 余白・形状

余白は4pxを基準に、次の値を使う。

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-6: 24px;
--space-8: 32px;
--space-12: 48px;

--radius-control: 8px;
--radius-card: 5px;
--radius-dialog: 16px;
```

- 入力項目間：16〜24px
- カード内余白：モバイル16px、広い画面24px
- セクション間：24〜32px
- ページ左右余白：モバイル16px、広い画面24〜32px

カードの角丸は、ホーム画面プレビューで選択した5pxを採用する。

カードは細い境界線を基本とする。影はダイアログや浮遊メニューなど、前後関係を示す箇所を中心に使う。

## 7. レイアウト・ナビゲーション

### 7.1 ページ構成

基本の並びを統一する。

1. 共通ヘッダー・ナビゲーション
2. パンくず（階層が深い画面）
3. ページタイトル・説明・主要操作
4. フィルターやタブ
5. 本文・一覧・フォーム
6. ページ送りや補助操作

ページ全体の最大幅は1200px、文章中心の詳細は800px、フォームは640pxを目安とする。

### 7.2 レスポンシブ

| 幅 | 基本方針 |
|---|---|
| 768px未満 | 1列、メニューを折りたたむ |
| 768〜1023px | 内容に応じて1〜2列 |
| 1024px以上 | 一覧やホームは2列、管理画面はサイドバーを使用可能 |

モバイルでも、主要操作、状態、エラーを省略しない。

管理テーブルの情報量が多い場合は、行をカード形式にするか、表の領域内で横スクロールする。ページ全体の横スクロールは避ける。

### 7.3 ナビゲーション

ホーム、Q&A、お知らせ、イベント、卒業生検索を既存画面設計に沿って配置する。通知と本人メニューはヘッダーからアクセスできるようにする。

管理機能は一般機能と区別したメニューにまとめる。管理画面では「管理エリア」と現在地を明示する。

選択中の項目は、背景・太字・マーカーなどを組み合わせ、`aria-current` を設定する。

## 8. 共通コンポーネント

### 8.1 ボタン

| 種類 | 表現 | 使用例 |
|---|---|---|
| 主要 | ネイビー背景・白文字 | ログイン、保存、質問を投稿 |
| 副次 | 白背景・ネイビー文字・境界線 | キャンセル、戻る |
| 補助 | 文字による操作 | 詳細を見る、条件をクリア |
| 危険 | 赤系背景・白文字 | 削除、停止の確定 |

- 同じ操作グループ内で主要ボタンを絞る。
- 高さは原則44px以上とする。
- ラベルは「保存する」「承認する」など操作を具体的に示す。
- 送信中は「保存中…」などの表示と二重送信防止を組み合わせる。
- 操作できない理由がある場合は、近くに説明を表示する。
- アイコンのみのボタンにはアクセシブルな名前を付ける。

### 8.2 入力欄

- ラベルを入力欄の上に常時表示する。
- プレースホルダーをラベルの代わりにしない。
- 必須項目には「必須」を表示する。
- 補足説明とエラーは対象項目の近くに表示する。
- エラー時も入力済みの内容を保持する。
- 複数エラーがある場合はフォーム上部にも案内を表示する。
- パスワードの表示切り替えには「表示」「非表示」の名前を付ける。

認証方式や入力制約は既存仕様に従う。PoC対象外の自己登録・パスワード回復画面への導線は設けない。

### 8.3 カード・一覧

カードは白背景、薄い境界線、5pxの角丸を基本とする。

表示順序：

1. カテゴリー・状態
2. タイトル
3. 要約または本文
4. 投稿者・日時などの補足
5. 必要な操作

カード内に複数の操作がある場合は、カード全体を単一リンクにしない。タイトルリンクと操作ボタンを分ける。

### 8.4 ダイアログ

- 目的、対象、操作結果を明示する。
- 確定操作には「はい」ではなく「削除する」などの名前を使う。
- 開いたときに内部へフォーカスを移し、閉じたときに元の操作へ戻す。
- キーボードフォーカスが背面へ移動しないようにする。
- 閉じる操作は暗黙の送信・確定を行わない。

確認ダイアログの要否は既存画面設計に従う。通報の送信前、公開済みお知らせの本人削除、公開済みイベントの本人中止は、必須の最終確認を実装する。

### 8.5 メッセージ

- 成功：「プロフィールを保存しました。」
- 入力エラー：「質問のタイトルを入力してください。」
- 更新競合：「内容が更新されています。最新の内容を確認してください。」
- 空状態：「まだ質問はありません。」
- 読み込み失敗：「読み込めませんでした。もう一度お試しください。」

入力エラー、競合、権限制限など、操作の継続に必要な情報は画面内に残す。短時間で消える通知だけに依存しない。

## 9. 最初に実装する画面

### 9.1 ログイン

- 白いカードをページ中央に配置する。
- 学校ロゴ、アプリ名、短い案内を表示する。
- 学校発行IDとパスワードを入力する。
- ネイビーのログインボタンを配置する。
- オレンジは小さな装飾に限定する。
- 利用開始・認証情報の問い合わせ案内は、配布方法が確定してから文言を設定する。

### 9.2 ホーム

既存設計に従い、Q&A・お知らせ・イベント・通知の4領域を、各5件を基本として表示する。

- モバイルは1列、広い画面では2列を基本とする。
- 見出しと「一覧を見る」の位置を揃える。
- 領域ごとに大きく配色を変えず、内容とラベルで区別する。
- ホーム内に長文を詰め込まず、詳細へ移動できるようにする。

### 9.3 プロフィール

- 表示名、所属、自己紹介などを読みやすく整理する。
- 所属と管理権限を別の情報として表示する。
- 編集画面では、任意項目の公開範囲を入力欄の近くに示す。
- 他者向けの表示では、公開を許可された情報だけを表示する。
- 非表示・再公開審査中などの案内は既存仕様に従う。

## 10. 権限・状態の見せ方

- UI上の表示制御は、サーバー側の認可判定に基づく。
- 管理者向け操作を一般操作と区別して配置する。
- 削除・停止・強制非表示などは、通常操作から間隔を空ける。
- 非公開情報を、隠し要素やHTML属性に含めない。
- 権限不足や対象の非表示・削除に関するメッセージは、APIの返却方針に従う。
- 審査・公開・開催の状態は別の概念として扱う。

たとえば、申請の「承認済み」と、イベントの「中止」は別ラベルで表示する。「緑色だから開催中」のような推測が必要な表示にしない。

## 11. アクセシビリティ・動き

- 通常文字のコントラスト比は4.5:1以上を基準とする。
- 操作部品の識別に必要な境界・アイコン・状態表示は3:1以上を基準とする。
- キーボードですべての主要操作を完了できるようにする。
- フォーカスは外周リングと背景との間隔で明示する。
- 操作領域は原則44×44px以上を確保する。
- 色に加え、ラベル、アイコン、形状で意味を伝える。
- 見出し階層とHTMLの意味を維持する。
- 成功通知やエラーは、支援技術でも確認できるようにする。
- 200%の拡大でも主要な情報と操作を利用できるようにする。

アニメーションはホバーや開閉などに限定し、150〜200msを目安とする。`prefers-reduced-motion` に対応する。

## 12. 実装・更新ルール

- 色・余白・角丸は共通のCSS変数で管理する。
- ページ固有のCSSに同じ色コードを繰り返さない。
- ブランド色と「主要操作」「エラー」などの用途別トークンを分ける。
- ボタン、入力欄、バッジ、メッセージ、ダイアログを共通化する。
- 既存のCSS構成に合わせて実装し、UIライブラリの導入は別途判断する。
- 最初にログイン・ホーム・プロフィールで確認し、他画面へ展開する。
- 実装で共通ルールを変更した場合は、本書も更新する。

正式なロゴ素材・使用条件と学校指定のカラー値は、入手後に本書へ反映する。

## 13. 画面の確認項目

- ロゴの縦横比と読みやすさが保たれている。
- ブランド色と用途別カラーを一貫して使用している。
- 本文、リンク、ボタンのコントラストが確保されている。
- モバイルで情報や主要操作が欠けない。
- 読み込み中、空、成功、エラー、操作不可の表示がある。
- 権限と対象の状態に応じて操作が表示される。
- キーボード操作とフォーカス表示を確認できる。
- 入力エラー時に内容が保持される。
- 二重送信と更新競合を画面内で案内できる。
- PoC対象外の機能への導線が追加されていない。
