## 1. 背景・目的と適用範囲

専門学校の在校生・卒業生・学校が、就職活動・技術学習・制作・イベント案内を安全に共有する、学校関係者向けのクローズドなWebコミュニティを提供する。

学校側の承認を得た利用者のみ閲覧できる。初期導入では現4年生を卒業予定者として先行登録し、卒業時に学校管理者が一括で卒業生へ切り替える。

### 1.1 MVPの8領域

| **領域** | **対象**                                                            |
|----------|---------------------------------------------------------------------|
| **01**   | 認証・登録：メール確認、登録審査・履歴、区分変更                    |
| **02**   | プロフィール：公開範囲、卒業生検索、非表示・再公開                  |
| **03**   | Q&A掲示板：質問・回答・返信・検索・解決状態                         |
| **04**   | お知らせ：学校公式／卒業生の発信・審査・編集・削除・強制非表示      |
| **05**   | イベント：開催告知・審査・終了／中止・外部申込導線・強制非表示      |
| **06**   | 通知：必要なアプリ内通知                                            |
| **07**   | 通報・安全管理：Q&A・プロフィール・アカウントの通報、案件管理・監査 |
| **08**   | 管理者機能：登録・お知らせ・イベント審査、通報・利用者管理          |

### 1.2 MVP対象外

学校外公開、個別DM、Microsoft 365必須認証、イベントアプリ内申込・出欠管理、決済、掲示板への画像・ファイル添付、通常メール／プッシュ通知、お知らせのコメント・返信・いいね・ピン留め・掲載終了日・自分のお知らせ検索、お知らせ・イベントの通報、通報履歴の本人向け一覧。

## 2. 利用者・権限モデル

| **ロール**       | **位置付け**                                                                         |
|------------------|--------------------------------------------------------------------------------------|
| **在校生**       | 学校承認後にQ&A・プロフィール閲覧/編集・イベント申請等が可能。お知らせ投稿不可。     |
| **卒業予定者**   | 在校生の特別な状態。本人希望で検索対象。卒業時の区分変更は学校管理者。               |
| **卒業生**       | Q&A・お知らせ申請・イベント申請。                                                    |
| **学校職員**     | 学校管理者が個別アカウント作成。お知らせとイベントは即時公開。                       |
| **学校管理者**   | 学校側の最上位管理権限。初回登録審査・本人確認情報・任命・監査・学校専用案件を扱う。 |
| **アプリ管理者** | 学校管理者が承認済み利用者に付与・解除。所属区分の制限を原則維持し、通常運営を担当。 |

所属区分（在校生／卒業生／学校職員）と管理権限（学校管理者／アプリ管理者）は別軸で扱う。学校管理者は学校側担当者として想定し、卒業生兼学校管理者は設計対象外。

| **操作**                   | **在校生** | **卒業生** | **学校職員** | **学校管理者**   | **アプリ管理者** |
|----------------------------|------------|------------|--------------|------------------|------------------|
| **コミュニティ閲覧**       | ○          | ○          | ○            | ○                | ○                |
| **Q&A 投稿・返信**         | ○          | ○          | ○            | ○※               | ○※               |
| **お知らせ新規**           | ×          | 申請       | 即時         | 所属依存         | 所属依存         |
| **イベント新規**           | 申請       | 申請       | 即時         | 学校職員なら即時 | 所属依存         |
| **登録審査**               | ×          | ×          | ×            | ○                | ×                |
| **お知らせ／イベント承認** | ×          | ×          | ×            | ○                | ○※               |
| **通常の通報管理**         | ×          | ×          | ×            | ○                | ○（限定）        |
| **通報証拠（削除後）**     | ×          | ×          | ×            | ○                | ×                |
| **管理者操作ログ閲覧**     | ×          | ×          | ×            | ○                | ×                |

※ 管理者も本人の基本ロールを保持する。アプリ管理者による自己申請承認・却下は禁止。プロフィール非表示中・アカウント停止中などの制限は常に優先する。

## 3. 登録・認証とプロフィール

### 3.1 登録・認証

| **ID**    | **要件（v1.1）**                                                                                                                                              |
|-----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **AC-01** | メールアドレス＋パスワードでログインする。登録時にメールアドレスの確認を行う。                                                                                |
| **AC-02** | 登録申請時に実名、所属区分、学科・コース、入学年／卒業年などの本人確認に必要な情報と、公開表示名を区別して収集する。具体的な必須項目は学校確認を要する。      |
| **AC-03** | 初回登録申請の承認・却下は学校管理者のみが実施する。アプリ管理者は審査できない。                                                                              |
| **AC-04** | 承認されるまで、申請者は申請状況のみ確認可能。掲示板を含むコミュニティ内の閲覧・投稿を禁止する。                                                              |
| **AC-05** | 審査待ちの登録申請は本人・学校管理者とも申請内容を変更しない。                                                                                                |
| **AC-06** | 却下理由は任意。入力があれば本人に表示する。未入力時は却下の事実のみ表示する。                                                                                |
| **AC-07** | 却下後は本人が修正して再申請でき、回数制限はない。再申請は新しい審査として扱う。                                                                              |
| **AC-08** | 過去の申請内容・却下理由・審査日時などの履歴は学校管理者のみ確認できる。本人には最新申請の状況のみ表示する。                                                  |
| **AC-09** | 新規申請・再申請の際は学校管理者宛てにアプリ内通知。審査結果は本人がログインして状態確認し、通常メール通知は行わない。                                        |
| **AC-10** | 承認後の本人確認情報の本人による変更申請機能はMVPでは実装しない。                                                                                             |
| **AC-11** | 「登録申請管理」は学校管理者専用画面とし、初期表示は申請中。承認済み・却下済みと履歴を確認できる。                                                            |
| **AC-12** | 学校職員アカウントは学校管理者が管理画面で個別作成し、本人が初回の認証情報を設定する。一般の登録申請・審査フローを利用しない（AUTH-03）。                     |
| **AC-13** | 最初の学校管理者は、学校が指定した担当者についてシステム管理担当者が初期構築時にサーバー側で作成する。本人が認証情報を設定し、作成操作を記録する（AUTH-18）。 |
| **AC-14** | アプリ管理者権限の解除後もログイン状態と基本所属区分を維持するが、管理画面・管理APIへのアクセスは解除確定時点から即時拒否する（AUTH-19）。                    |

### 3.2 プロフィール・卒業生検索

| **ID**    | **要件（v1.1）**                                                                                                                                                                                                             |
|-----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **PR-01** | 本人確認用の実名・メールアドレス・学籍照合情報は公開プロフィールと分離し、他人の非公開本人確認情報の閲覧は学校管理者に限定する。アプリ管理者は公開表示名・ユーザーID等、権限内の運営情報のみ閲覧できる（AUTH-01／CONS-03）。 |
| **PR-02** | 所属区分・学科・年度などの基本プロフィールを表示する。その他の任意項目は本人が公開範囲を選択できる。                                                                                                                         |
| **PR-03** | 卒業生検索は掲載希望者のみ対象とし、卒業予定者も本人希望により検索対象へ含める。                                                                                                                                             |
| **PR-04** | 卒業後も同じアカウント・過去投稿・プロフィール履歴を引き継ぐ。卒業予定者から卒業生への一括変更、および誤変更の修正は学校管理者のみが行い、変更履歴を残す（AUTH-11／24）。                                                    |
| **PR-05** | 不適切プロフィールは管理者が一時非表示にできる。アプリ管理者本人のプロフィール非表示・再公開審査は学校管理者のみ。非表示中は本人の新規投稿・コメントを制限し、アプリ管理者の管理機能も一時停止する（AUTH-07／20）。          |
| **PR-06** | 非表示中も過去投稿は公開を維持し、本人は既存投稿の削除のみ可能（編集不可）。                                                                                                                                                 |
| **PR-07** | プロフィールの修正保存により再公開申請を自動生成する。審査中の再編集は可能で、却下時には理由を通知し、承認時にも通知する。                                                                                                   |
| **PR-08** | 学校管理者は卒業予定者の区分一括変更・誤変更修正を実行できる。学校職員・アプリ管理者・本人は区分変更不可。変更前後・実行者・日時を記録する（AUTH-11／24）。                                                                  |
| **PR-09** | アプリ管理者のプロフィール非表示中は管理ロールを保持したまま管理機能を一時停止。再公開承認後は、停止・権限解除などの別制限がなければ利用可能に戻す（AUTH-20）。                                                              |

## 4. Q&A掲示板

| **ID**    | **要件（v1.1）**                                                                                                                                       |
|-----------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| **QA-01** | 認証済みの通常利用者は、掲示板に質問・回答・コメントを事前承認なしで投稿できる。                                                                       |
| **QA-02** | カテゴリーは「就職・キャリア」「技術・学習」「制作・プロジェクト」「雑談」の4種類とする。                                                              |
| **QA-03** | コメントへの返信（スレッド）を可能とする。                                                                                                             |
| **QA-04** | 質問には未解決／解決済みの状態を設ける。状態の変更は質問者本人のみが何度でも実行できる。解決済みでも回答・コメントを受け付ける（AUTH-08／08-2）。      |
| **QA-05** | 本人は投稿・回答を編集・削除できる。元の投稿を削除しても回答・コメントは原則残す。                                                                     |
| **QA-06** | キーワード検索と絞り込みを実装する。                                                                                                                   |
| **QA-07** | 本文では制限されたMarkdownを利用可能とする（許可構文は詳細設計で定義）。                                                                               |
| **QA-08** | MVPでは投稿への画像・ファイル添付を実装しない。                                                                                                        |
| **QA-09** | 通知はアプリ内のみとし、具体的なトリガーは既定の掲示板通知方針に従って設計する。                                                                       |
| **QA-10** | 質問者本人のみ未解決／解決済みを回数制限なく切替可能。第三者・管理者は他人の質問の解決状態を変更できない（AUTH-08／08-2）。                            |
| **QA-11** | アプリ管理者が投稿したQ&A質問・回答・コメントに対する管理者強制非表示・復元は学校管理者のみ実行可能。本人の通常編集・削除権限は従来どおり（AUTH-22）。 |

## 5. お知らせ

| **ID**    | **要件（v1.1）**                                                                                                                                                                                                                                  |
|-----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **NO-01** | 新規お知らせを投稿できるのは学校職員・卒業生のみ。在校生は閲覧・検索のみ。                                                                                                                                                                        |
| **NO-02** | 学校職員の新規投稿・編集は承認を要さず即時公開する。                                                                                                                                                                                              |
| **NO-03** | 卒業生の新規投稿は学校管理者またはアプリ管理者の承認後に公開する。                                                                                                                                                                                |
| **NO-04** | 卒業生が公開済みお知らせを編集した場合は再承認が必要。承認されるまでは旧公開版を維持する。却下時も旧版を維持する。                                                                                                                                |
| **NO-05** | 新規申請・編集申請が承認待ちの間、申請者は申請内容を編集できない。                                                                                                                                                                                |
| **NO-06** | 承認待ち申請は本人が取り下げられる。公開済みの編集申請を取り下げても旧公開版は維持する。取り下げ済み申請は閲覧専用履歴とする。                                                                                                                    |
| **NO-07** | 却下理由は新規・編集申請とも任意。却下後は修正して再申請可能とし、過去の却下履歴を保持。再申請日時で新しい審査を作る。                                                                                                                            |
| **NO-08** | 承認管理画面では編集申請の「変更後の内容のみ」を表示し、差分・並列比較は設けない。                                                                                                                                                                |
| **NO-09** | 学校・アプリ管理者が審査できる。ただしアプリ管理者は自分の申請を承認・却下できず、自己申請は一覧に表示したまま操作不可とする。                                                                                                                    |
| **NO-10** | 新規申請・却下後の再申請時、審査可能な管理者へアプリ内通知する。申請者本人がアプリ管理者の場合、自分宛ての審査依頼通知は送らない。                                                                                                                |
| **NO-11** | 承認管理画面は審査状況「承認待ち（初期）／承認済み／却下済み」と申請種別「すべて（初期）／新規申請／編集申請」を組み合わせて絞り込める。承認待ちは申請日時が古い順。                                                                              |
| **NO-12** | 取り下げ済み申請は承認管理一覧・履歴に表示せず、送信済み通知を開くと取り下げ済みの案内のみ表示する。取り下げ自体の通知は送信しない。                                                                                                              |
| **NO-13** | 一般向け一覧は「初回公開日時が新しい順」に固定する。編集・再承認後も初回公開日時を維持し、並び順切替は設けない。                                                                                                                                  |
| **NO-14** | 一般向けお知らせ一覧は公開中のタイトル・本文をキーワード検索できる。編集申請中は旧公開版のみ検索対象とする。                                                                                                                                      |
| **NO-15** | 掲載終了日・固定表示・コメント・返信・いいね・通報機能は実装しない。新規公開時の一般利用者への一斉通知は送らない（AUTH-14）。                                                                                                                     |
| **NO-16** | 「自分のお知らせ」は初期フィルター「すべて」。承認待ち／公開済み／却下済み／取り下げ済み／削除済み等を個別に絞り込める。検索機能は設けない。                                                                                                      |
| **NO-17** | 本人向け一覧の並び順は「作成日時が新しい順（初期）」と「最終更新日時が新しい順」を切り替え可能。                                                                                                                                                  |
| **NO-18** | 公開済みお知らせは投稿者本人が管理者承認なしで削除可能。削除前の最終確認を必須とする。                                                                                                                                                            |
| **NO-19** | 削除確定時、一般利用者から即時非表示とし論理削除する。承認待ち編集申請があれば自動取り下げる。                                                                                                                                                    |
| **NO-20** | 削除済み本体は復元・再公開不可。再掲は新しいお知らせを新規作成し通常の承認フローを適用する。                                                                                                                                                      |
| **NO-21** | 削除済み本体は削除から180日保存し、期限後自動消去する。一般利用者・アプリ管理者は本体を閲覧不可。学校管理者と投稿者本人は保存期間内のみ閲覧可能。                                                                                                 |
| **NO-22** | 「自分のお知らせ」に削除済み一覧・専用フィルターを設け、投稿者本人は削除後180日以内に本文を閲覧できる（編集・復元不可）。180日到来時に本体を自動消去し、本人向け削除済み一覧からも除外する（AUTH-12）。自動取り下げ編集申請履歴は別の定めに従う。 |
| **NO-23** | お知らせ本体の期限到来による消去は、別管理される証拠や監査記録が別途存在する場合の既定保存期限を短縮しない。ただしMVPではお知らせへの新規通報機能は設けない（AUTH-09／14）。                                                                      |
| **NO-24** | お知らせには通報機能を設けない。学校公式・卒業生投稿の双方を対象外とする（AUTH-14）。                                                                                                                                                             |
| **NO-25** | 学校公式お知らせの強制非表示・復元は学校管理者のみ。卒業生お知らせは学校管理者・アプリ管理者の双方が実行可能（AUTH-15／15-2／15-3）。                                                                                                             |

| **対象**                             | **代表的な状態遷移**                                                                                  |
|--------------------------------------|-------------------------------------------------------------------------------------------------------|
| **アカウント申請**                   | 申請中 → 承認済み／却下済み → （却下後）修正・再申請 → 申請中                                         |

| **公開済みお知らせ編集**             | 公開済み旧版 + 編集申請待ち → 編集承認で新公開版／却下・取り下げで旧版維持                            |
| **お知らせ削除**                     | 公開済み → 最終確認 → 論理削除（本人・学校管理者閲覧、180日後本体消去）。編集申請中なら自動取り下げ。 |
| **イベント**                         | 申請中 → 公開済み／却下／取り下げ。公開済み → 開催終了または中止（終了後の通常編集不可）。            |
| **通報案件**                         | 未対応 → 対応中 → 対応済み（優先度・担当者を付与、監査記録を保存）。                                  |
| **強制非表示（お知らせ／イベント）** | 公開中 → 強制非表示 → 権限管理者が復元 → 公開。削除と中止は別の状態軸。                               |
| **通報の引継ぎ**                     | 未対応／対応中 → 引継ぎ待ち（担当者一時なし） → 学校管理者による担当再設定。                          |

## 10. 受入条件・主要テストケース

| **ID**    | **期待結果**                                                                                                                  |

| **AT-13** | 公開中イベントを中止すると中止表示に変わり、予定内容や外部URLは既定どおり表示される。                                         |
| **AT-14** | 通報対象者から通報者の身元が見えず、権限がある管理者だけが確認できる。                                                        |
| **AT-15** | 並行して同じ申請を承認しても、重複処理や不正な状態遷移が起こらない。                                                          |
| **AT-16** | アカウント停止中はログイン後も閲覧・投稿などの機能利用が拒否される。                                                          |
| **AT-17** | アプリ管理者は他人の非公開本人確認情報・削除済みコンテンツ証拠・操作ログをAPIから取得できない。                               |
| **AT-18** | 学校職員兼アプリ管理者のイベント・お知らせ新規投稿は即時公開され、卒業生兼アプリ管理者は自己承認できない。                    |
| **AT-19** | 学校公式のお知らせ・学校職員イベントをアプリ管理者が強制非表示・復元できない。                                                |

| **AT-22** | 通報対象投稿の削除時、担当アプリ管理者の未対応・対応中案件は学校管理者専用引継ぎ待ちとなり、本人に証拠は公開されない。        |
| **AT-23** | 通常通報案件の担当者は両管理者が設定・変更でき、引継ぎ待ちは学校管理者のみ設定できる。                                        |
| **AT-24** | 通報者の公開表示名・ユーザーIDだけが通常通報案件のアプリ管理者へ返され、実名・メールアドレスは返されない。                    |
| **AT-25** | イベント／お知らせの通報APIは存在しないか拒否され、Q&A／プロフィール／アカウントの通報は可能。                                |
| **AT-26** | 学校管理者が卒業区分を変更・誤変更修正できるが、本人・アプリ管理者は不可。履歴が記録される。                                  |
| **AT-27** | 権限解除後もログインは維持する一方、管理APIへのアクセスは即時拒否される。                                                     |
| **AT-28** | お知らせ・イベント強制非表示／復元の理由は未入力でも受け付け、操作監査ログを必ず保存する。                                    |
